# AKADE CITY 效能與硬體規格

> 依 Steam 硬體調查調整畫質預設、自動判斷與效能測試的說明。
> 程式在 `components/city-game/`：`graphicsSettings.ts`、`adaptiveQuality.ts`、`frameGate.ts`、`timestep.ts`、`groundWorker.ts`、`bench.ts`。

## 1. 參考資料：Steam 硬體調查（2026 年 8 月）

來源：<https://store.steampowered.com/hwsurvey/>、<https://store.steampowered.com/hwsurvey/videocard/>

| 項目 | 主流分布 |
|---|---|
| 主螢幕解析度 | 1920×1080 50.5%、2560×1440 21.9%、2560×1600 5.7%、3840×2160 5.0%、3440×1440 3.1% |
| 顯示卡（前幾名） | RTX 3060 3.9%、RTX 4060 Laptop 3.8%、RTX 5070 3.8%、RTX 4060 3.6%、RTX 3050 3.2%、RTX 5060 3.2% |
| 仍占一定比例的入門卡 | GTX 1650 2.5%、Intel Iris Xe 1.7%、AMD Radeon 內顯 1.7%、GTX 1060 1.5% |
| CPU 實體核心 | 8 核 28.0%、6 核 27.4%、10 核 7.5% |
| 記憶體 | 16 GB 41.2%、32 GB 37.5%、8 GB 7.5% |
| 顯示記憶體 | 16 GB 26.9%、8 GB 25.7%、12 GB 13.0% |
| 作業系統 | Windows 94.0%、Linux 3.9%、macOS 2.1% |

解讀：

- 一半玩家是 1080p，另外約三成的螢幕比 1080p 大。所以解析度要有「像素預算」，不能直接照螢幕原生解析度渲染。
- 典型顯卡是 RTX 3060 / 4060 等級，跑中到高畫質沒問題。
- 記憶體和顯存都不是瓶頸。
- 遊戲邏輯是單執行緒 JS，多核心 CPU 原本完全用不到，所以把地面貼圖繪製搬到 Web Worker。
- Steam 偏向玩家族群，網頁遊戲會有更多筆電和內顯，所以低畫質和自動降級都要保留。

## 2. 規格對照

| 規格 | 代表硬體 | 自動選用 | 目標 |
|---|---|---|---|
| 最低 | Intel Iris Xe / UHD、AMD Radeon 內顯、GTX 1050 | 低 | 1080p 螢幕，30 fps |
| 建議 | GTX 1650 / 1660 / 1060、RTX 3050 / 4050、Radeon 780M | 中 | 1080p，60 fps |
| 高 | RTX 2060 以上、RTX 3060 / 4060 / 5060 以上、RX 6600 以上 | 高 | 1080p–1440p，60 fps |
| 極致 | RTX 4070 以上，從選單手動開啟 | 不會自動選 | 原生解析度，含 SSR |

## 3. 各畫質內容（`PRESETS`）

| | 低 | 中 | 高 | 極致 |
|---|---|---|---|---|
| 像素上限 `maxPixels` | 1.2 MP（約 1440×810） | 2.1 MP（1080p） | 3.7 MP（1440p） | 不限 |
| 更新率上限 | 30 | 60 | 60 | 60 |
| 陰影 | 關 | 中（2048） | 高（4096） | 極致 |
| 後製 | 無 | Bloom + MSAA | Bloom + GTAO + SMAA | 再加 SSR |
| 車流 / 行人 / 路燈光源 | 8 / 32 / 0 | 15 / 67 / 2 | 22 / 96 / 6 | 31 / 125 / 12 |

- **解析度**：`resolutionScale` 是「原生解析度的比例」，再用 `renderDpr()` 壓進像素上限。例如中畫質：
  - 1080p 螢幕：原生渲染。
  - 1440p 螢幕：約 1932×1087。
  - 4K 螢幕（Windows 150% 縮放）：同樣約 1080p 的像素量。
  - 暫停選單的「解析度」下方會顯示實際渲染尺寸。
- **更新率**：選項有 不限 / 144 / 120 / 60 / 30。沒有上限時，144Hz 螢幕每秒會模擬和繪製 144 次，所以中畫質以上預設 60。
- **MSAA**：只有 MSAA 單獨負責反鋸齒時，才建立多重取樣的 canvas（`canvasMsaa`）。低畫質不再付這個成本。切換時 canvas 會重建。

## 4. 顯卡自動判斷（`detectTier`）

- 第一次開啟時，在建立遊戲 canvas 之前，先用拋棄式 WebGL context 讀顯卡名稱（`gpuProbe.ts`），然後套用對應畫質。
- 之後只會儲存玩家（或自動調整）改過的設定。`GFX_VERSION` 升到 3，舊設定會重設一次。

| 畫質 | 型號 |
|---|---|
| 低 | 軟體渲染、Intel HD / UHD / Iris、AMD Radeon Graphics / Vega 內顯、GT / MX、GTX 9xx / 1050 / 1630、手機 GPU、所有觸控裝置 |
| 中 | GTX 1060–1080、1650 / 1660、RTX x050、Radeon 680M / 780M / 880M / 890M、RX 5500 / 6400 / 6500、RX 470–590、Intel Arc A3xx 與 Arc 內顯、Apple M 系列基本款、Firefox 的「or similar」通用名稱、無法辨識 |
| 高 | RTX x060 以上（20–50 系列）、RTX A 系列工作站卡、RX 5600 / 6600 / 7600 / 9060 以上、Arc A5xx / A7xx / B 系列、Apple M Pro / Max / Ultra |

測試：`graphicsSettings.test.ts` 用 Steam 前 25 名顯卡的 ANGLE 字串逐一驗證。

## 5. 自動調整畫質（`adaptiveQuality.ts`）

- PostFX 每 0.5 秒回報一次實際繪製的 fps。
- 目標 fps 取 `min(更新率上限, 60)`，不限時取 60。實際 fps 連續 5 秒低於目標的 80% 才會動作：
  1. 像素預算乘 0.75，最低到 50%（1 → 0.75 → 0.56 → 0.5）。
  2. 降一個畫質等級。自訂設定不會被換成預設檔，只會調像素預算。
- 只會往下調，不會自動往上。
- 載入後 10 秒內、暫停或開選單時、分頁切到背景後，以及每次調整後 4 秒內，都不做判斷。
- 效能測試進行中也不做判斷。
- 暫停選單可以關閉「自動調整畫質」。另外，手動調整解析度或選擇畫質會清除自動降的解析度。

## 6. 幀率與模擬

- **幀率上限閘門（`frameGate.ts`）**：GameScene 在 `useFrame(-2)` 決定這一幀要不要跑。模擬、繪製、雨雪粒子、地面串流、巡邏機都讀同一個結果。
  - 閘門會保留餘數，所以 144Hz 螢幕設 60 上限時實際是 60 fps。舊做法只有 48。
- **AI 車速與幀率無關（`timestep.ts`）**：`speed` 仍然是「每個 60Hz 幀」的像素數，位置積分乘上 `frameScale(dt)`，每幀衰減改用 `decay(k, dt)`。
  - 效果：開闊道路上 30 / 60 / 144Hz 的速度都是 120 px/s。舊版分別是 60 / 120 / 288。
  - 原本用幀數算的計時也改成秒數（`Cadence`）：補車流 1 秒、景點發現 0.25 秒、GPS 1/6 秒、行人清除 1/6 秒、小地圖 10Hz。
- **已知問題（尚未處理）**：車道路徑每個路塊（40px）一個路標，而路標前 40px 的減速區會每幀累乘，導致市區車流平均只有約 6 px/s。這是 HEAD 就有的狀況，和幀率無關（已驗證 HEAD 在各幀率都是 5.9 px/s）。修正會明顯改變遊戲手感，所以另外處理。

## 7. 主執行緒 CPU

- **地面貼圖改在 Web Worker 繪製（`groundWorker.ts`）**：
  - 格子資料以兩個 typed array（共 50 KB）傳一次過去。
  - 每個 512² 區塊在 OffscreenCanvas 上畫好，以 `ImageBitmap` 轉移回來，不複製。
  - `ImageBitmap` 不支援 `UNPACK_FLIP_Y`，所以改用貼圖 UV 翻轉（`repeat (1,-1)`、`offset (0,1)`）。
  - 不支援 Worker 或 2D OffscreenCanvas 的瀏覽器，會退回主執行緒繪製。
- **移除每幀的記憶體配置**：
  - combat hooks 只建立一次。
  - 所有系統共用同一個已綁定的 `isSolidAt`。
  - 戰車瞄準目標物件和碰撞的 `tracked[]` 都重複使用。
  - 通知只有真的有項目過期時才重建。
  - ShadowRig 的向量改成共用。
  - 巡邏機的探照燈節點只查一次。
  - 地面 LRU 只在區塊變動時排序。

## 8. 效能測試（`?bench=1`，僅開發環境）

1. 在自己的瀏覽器開 `http://localhost:3001/games/city-game?bench=1`。請不要用無頭瀏覽器，軟體 WebGL 只有約 1 fps，而且會吃滿 CPU。
2. 載入完成 3 秒後自動開始。玩家會步行巡迴市中心周圍 6 個固定路口，每個停 5 秒，鏡頭慢慢旋轉，總共 30 秒。
3. 結束後 Console 會印出 `console.table`，結果也存在 `window.__bench`。

| 欄位 | 意義 |
|---|---|
| `gpu` / `preset` / `render` / `fpsCap` | 顯卡、畫質、實際渲染尺寸、更新率上限 |
| `avgFps` | 實際模擬並繪製的幀數 ÷ 時間 |
| `p50Ms` / `p95Ms` / `p99Ms` | 繪製幀之間的間隔。p95、p99 代表卡頓程度 |
| `simMs` | 每幀 `engine.update` 的主執行緒毫秒數 |
| `drawCalls` / `triangles` | 每幀的繪製呼叫數和三角形數（包含所有後製 pass） |
| `heapMB` | JS heap 用量（僅 Chrome） |
